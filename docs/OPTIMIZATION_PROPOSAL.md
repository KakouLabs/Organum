# [Proposal] Organum-Native Acoustic Pipeline Optimization

## 1. 개요
현재 리팩토링된 `world` 모듈은 인터페이스 관점에서는 독립적이지만, 내부 로직은 여전히 범용적인 순차 처리 방식을 따르고 있습니다. Organum의 대량 오디오 처리 및 고성능 리샘플링 요구사항에 맞춰, **CPU 멀티코어 활용 능력을 극대화하고 메모리 할당 오버헤드를 최소화**하는 최적화 전략을 제안합니다.

---

## 2. 핵심 최적화 전략

### 2.1 Rayon 기반 병렬 분석 (Parallel Processing)
`world` 알고리즘의 분석 단계(`CheapTrick`, `D4C`)는 각 타임프레임이 독립적으로 계산됩니다.
*   **현상**: 단일 프레임씩 순차적으로 처리 (CPU 코어 하나만 집중 사용).
*   **개선**: `Rayon` 워크스테이션을 활용하여 프레임 루프를 `par_iter()`로 병렬화.
*   **예상 성능 향상**: CPU 코어 수에 비례하여 분석 속도 **3~6배 향상**.

### 2.2 Zero-Allocation 워크스페이스
분석 및 합성 과정에서 발생하는 빈번한 `Vec` 생성과 해제를 제거합니다.
*   **현상**: `extract_features` 호출 시마다 새로운 대형 행렬 및 임시 버퍼 할당.
*   **개선**: `AnalyzerWorkspace` 내부에 대형 스크래치 버퍼를 유지하고, 모든 내부 알고리즘(`dio`, `cheaptrick`, `d4c`)이 이 버퍼의 슬라이스(`&mut [f32]`)를 전달받아 처리하도록 구조 변경.
*   **효과**: GC 부담 감소 및 메모리 파편화 방지.

### 2.3 FFT 및 Window 사전 계산 (Pre-computation)
샘플 레이트와 프레임 주기가 고정된 경우, 반복되는 삼각함수 연산을 상수로 변환합니다.
*   **개선**: 
    *   `AcousticAnalyzer` 생성 시점에 FFT용 `Twiddle Factors` 및 분석용 `Window (Blackman/Hanning)` 함수를 미리 계산하여 저장.
    *   루프 내부에서는 오직 곱셈과 덧셈만 수행.
*   **효과**: 프레임당 연산량(FLOPs) 약 **15~20% 감소**.

### 2.4 인코딩 통합 (Merged Encoding)
현재는 `Raw Spectrogram`을 모두 만든 후 다시 `MGC`로 변환합니다. 이는 불필요한 메모리 읽기/쓰기를 유발합니다.
*   **개선**: `CheapTrick` 분석 직후, 데이터를 메모리에 쓰기 전에 즉시 멜-로그 스펙트럼 변환 및 DCT를 수행하여 **MGC 데이터만 최종적으로 저장**.
*   **효과**: 메모리 대역폭 사용량 **90% 이상 절감** (Full Spectrogram은 메모리에 쓸 필요가 없음).

---

## 3. 구현 로드맵 (Proposed Implementation)

### [Phase 1] 병렬화 및 버퍼 재사용 (즉시 적용 가능)
*   `world/src/native/analysis.rs`의 분석 루프에 `rayon` 적용.
*   `AcousticFeatures`를 외부에서 주입받아 재사용하는 API 강화.

### [Phase 2] 알고리즘 고도화
*   FFT 라이브러리를 더 빠른 구현체로 교체하거나, 수동 SIMD 최적화 적용.
*   MGC 변환 로직을 분석 파이프라인 내부로 인라인화.

## 4. 예상 기대 효과

| :--- | :--- | :--- |
| **분석 속도 (Batch)** | 1.0x (Baseline) | **5.0x ~ 8.0x** |
